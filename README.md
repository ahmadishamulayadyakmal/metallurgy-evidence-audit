# Cross-case evidence audit and public release (C12)

## Industrial problem

Across eleven cases, an engineering organisation must be able to answer: which published numbers did we actually reproduce, which are external literature, and which claims are unsafe to put in a decision memo?

**Why it happens.** Aggregated portfolios blur 'we measured' and 'the paper reports' — exactly the reproducibility failure studied in C01.

## Data (no plant data)

Open data only: the outputs, checksums and provenance manifests of C01–C11, all generated locally from open data.

> Only open datasets and published literature are used. No plant or proprietary data are held here; plant numbers quoted from papers are external literature, not independently reproduced results.

## Tool chain

BibTeX / `CITATION.cff`, V&V audit against R31, figure regeneration scripts, Zenodo `v1.0.0` DOI, static portfolio site / dashboard, preprint.

## Journal references

- **R31** — the audit standard for verification, validation and uncertainty claims.
- **R01** ([DOI](https://doi.org/10.1126/science.277.5330.1237)) — the ICME narrative tying the cases together.
- **R05** ([DOI](https://doi.org/10.1038/s41586-018-0337-2)) — ML pipeline reporting checklist.
- **R07** ([DOI](https://doi.org/10.1016/j.commatsci.2018.05.018)) — citation of data tooling.
- **Y2R12** ([DOI](https://doi.org/10.1186/2193-9772-3-8)) — error-modality warning used as the worked audit example.

## Deliverables

`v1.0.0` release; Zenodo DOI; preprint / technical article; 12 paper-format case READMEs; dashboard regenerated by script; table of reproduced vs external numbers for all cases.

## Validation & claims

Clean-checkout reproduction; every reported number is traceable to a dataset checksum or a DOI, with external literature labelled as such.

## Limitations

Publication layer only; the physics lives in E01–E11. No publisher PDFs are committed.
