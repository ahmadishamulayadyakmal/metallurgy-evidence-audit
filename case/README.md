**Repository:** `e12-release-paper-portfolio` · **Evidence: A** ·
**References:** R01, R05, R31, Y2R12.

**Industrial problem.** Across eleven cases, an engineering organisation must be
able to answer: which published numbers did we actually reproduce, which are
external literature, and which claims are unsafe to put in a decision memo?

**Why it happens.** Aggregated portfolios tend to blur "we measured" and "the
paper reports". That is exactly the reproducibility failure of C01.

**Data (open, no plant data).** The outputs, checksums and provenance manifests of
C01–C11, all generated locally from open data.

**Tool chain.** BibTeX / `CITATION.cff` → `JOURNALS.md` download list → V&V audit
against R31 → evidence-level table → figure regeneration scripts → cross-case
article → Zenodo `v1.0.0` DOI → portfolio site / dashboard.

**What each reference validates.**
- R31 — the audit standard for verification, validation and uncertainty claims.
- R01 — the ICME narrative tying the cases together.
- R05 — ML pipeline reporting checklist.
- Y2R12 — error-modality warning used as the worked audit example.

**Deliverables.** `v1.0.0` release; Zenodo DOI; preprint / technical article;
12 paper-format case READMEs; dashboard regenerated by script; completed
`JOURNALS.md` checklist; a table of reproduced vs external numbers for all cases.

**Validation.** Third-party clean-state reproduction; every A-level number
traceable to a dataset checksum; every B-level number traceable to a DOI.

**Acceptance.** The audit table is complete for all 12 cases and no case claims
plant validation.
